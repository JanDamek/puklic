# iOS Port — Architecture Plan (2026-05-24)

## Summary

Puklic already has scaffolding for iOS (`:ios:app`, `:ios:platform`, `puklic.ios-library` convention plugin with iosArm64 / iosSimulatorArm64 / iosX64 targets) but every `:shared:*` module currently only ships `jvmMain` actuals. The port is mechanically straightforward for chat, persistence, networking, and DI — every dependency already on the classpath (Ktor, SQLDelight, Koin, Decompose, Compose Multiplatform 1.8.0, kotlinx.serialization, Kermit) is KMP-native and supports iOS. Real work concentrates on voice (AVAudioEngine actuals + libopus xcframework via cinterop + Network.framework UDP transport, replacing JavaCPP FFmpeg/JNA), the Swift host project (handwritten `PuklicApp.xcodeproj` + `embedAndSignAppleFrameworkForXcode` Gradle task), and unavoidable iOS UX regressions (no background gateway → no real push notifications; screenshare permanently impossible per Apple sandbox; DAVE blocked until libdave gets iOS build ~3-4 weeks). v1 scope: login + Keychain, full chat, DMs, audio-only voice without DAVE, foreground-only notifications. Distribution: TestFlight first ($99/yr Apple Developer); AltStore PAL for EU; App Store carries ~50/50 rejection risk.

## 1. Goal & non-goals

**Goal.** Native iOS app delivering login, full chat (read/send, reactions, attachments, markdown), DMs, audio-only voice with DAVE E2EE (when libdave-iOS arrives), APNs/local notifications, Keychain credential storage. Single Compose Multiplatform UI codebase shared with desktop.

**Non-goals v1 iOS:**
- Screenshare — Apple sandbox forbids capture of other apps' content
- Inline video render — defer to v2
- Native iOS HIG skin — ship Material widgets v1
- iPad split view / Stage Manager
- watchOS / tvOS / macCatalyst
- DAVE in first slice — voice ships without E2EE on iOS until libdave-iOS xcframework lands

## 2. Compose Multiplatform iOS maturity + pin

- Compose Multiplatform 1.8.0 (already pinned) — Stable for UI, Beta for some interop APIs
- Known sharp edges: IME quirks, scroll deceleration physics not 100% UIKit-native, soft keyboard inset adjustment
- **Pin:** keep `compose-multiplatform = "1.8.0"`; track 1.8.x patches
- **Kotlin pin:** `2.1.21` is fine for iOS
- **Deployment target:** keep `ios-deployment-target = "14.0"` (~99% device coverage)

## 3. Module structure changes

Existing layout already provisions iOS via `puklic.ios-library`. All `:shared:*` modules currently `jvmMain`-only.

**Required per shared module — add `iosMain` source set:**

| Module | Actuals needed |
|---|---|
| `:shared:platform-api` | Clock, Path, file, Logger (OSLog), AppDirs (NSFileManager) |
| `:shared:ids` | none — commonMain only |
| `:shared:domain` | none |
| `:shared:chat-parser` | none |
| `:shared:persistence-sqldelight` | `NativeSqliteDriver` |
| `:shared:protocol-discord` | none unless platform-specific bits |
| `:shared:session` | Keychain credential store |
| `:shared:compose-ui` | iOS window-insets shims, image loader |
| `:shared:voice` | `AudioCapture`/`AudioPlayback` via AVAudioEngine; `OpusCodec` via cinterop; UDP via Network.framework |
| `:shared:voice-dave` | libdave cinterop or stub |

Audit `puklic.kmp-library` plugin — must declare same three iOS targets as `puklic.ios-library` and apply default hierarchy template.

## 4. Dependency matrix per module

| Concern | iOS dependency |
|---|---|
| Networking | `io.ktor:ktor-client-darwin` (NSURLSession-backed) + ktor-client-websockets |
| Serialization | kotlinx.serialization 1.8.0 (KMP, no extra dep) |
| Coroutines | 1.10.1 (KMP, NSRunLoop main dispatcher) |
| Persistence | `app.cash.sqldelight:native-driver` (libsqlite3 from iOS SDK) |
| DI | Koin 4.1.0 (`koin-core`, no koin-android) |
| Navigation | Decompose 3.3.0 + Essenty 2.5.0 (KMP, manual LifecycleRegistry hooks) |
| Logging | Kermit 2.0.5 (OSLog) |
| Image loading | Coil 3.1.0 (Darwin, NSURLSession + UIImage) |
| Voice codec | libopus xcframework via cinterop |
| Voice crypto | **CryptoKit `ChaCha20Poly1305`** via cinterop (replaces BouncyCastle) |
| Voice MLS | libdave xcframework via cinterop OR Wire core-crypto-iosarm64 (0.6.0-rc) |

**Critical absences:** BouncyCastle and JavaCPP FFmpeg do not exist on iOS. The voice module's jvmMain has hard deps on both — `iosMain` needs different actuals.

## 5. libdave on iOS

Not in v1 scope. Long-term path:

1. Build OpenSSL `xcframework` for ios-arm64, ios-arm64-simulator, ios-x86_64-simulator (krzyzanowskim/OpenSSL prebuilds exist)
2. Build mlspp with `-DCMAKE_SYSTEM_NAME=iOS -DCMAKE_OSX_ARCHITECTURES=arm64 -DCMAKE_OSX_DEPLOYMENT_TARGET=14.0`. Disable mlspp tests.
3. Build libdave same way; bundle libopus into xcframework or link separately
4. Wrap with Kotlin/Native **cinterop** `.def` file targeting libdave's C ABI shim
5. Produce single multi-arch `Dave.xcframework`; ship via Gradle as resource consumed by `:shared:voice-dave`'s iosMain

**Estimate:** 3-4 weeks for build pipeline + cinterop + arch matrix CI. Defer until voice MVP on iOS works unencrypted.

**Interim:** v1 iOS connects to voice in non-DAVE channels; show banner "E2EE not yet supported on iOS — voice unavailable in DAVE-required channels."

## 6. Audio capture/playback — AVAudioEngine

- **Engine:** single `AVAudioEngine`; `inputNode` for capture, `outputNode` sink fed by `AVAudioPlayerNode` via `AVAudioMixerNode`
- **Format:** `AVAudioFormat(commonFormat: .pcmFormatInt16, sampleRate: 48000, channels: 1, interleaved: true)`. Install a tap on inputNode; resample with `AVAudioConverter` to 48kHz mono S16LE if device-native differs.
- **Frame size:** 960 samples (20 ms). AVAudioEngine doesn't guarantee exact buffer; implement ring buffer yielding 20 ms frames downstream.
- **Session:**
  ```swift
  AVAudioSession.sharedInstance().setCategory(.playAndRecord, mode: .voiceChat,
      options: [.allowBluetooth, .defaultToSpeaker])
  ```
  `mode: .voiceChat` gives free AEC + AGC + noise suppression — replaces what desktop builds manually.
- **Permission:** `NSMicrophoneUsageDescription` in Info.plist
- **Background:** `UIBackgroundModes` must include `audio` to keep voice running when locked
- **Interruptions:** observe `AVAudioSession.interruptionNotification`; pause/resume engine (Apple review requirement)
- **Route change:** observe `routeChangeNotification` for headphone unplug → mute mic, or BT route changes

## 7. Opus on iOS

- **Recommended:** prebuild `libopus.xcframework` (~300 KB per arch) from `xiph/opus` with standard iOS cmake toolchain. Bundle in `:shared:voice/src/iosMain/resources` or as `.klib` via cinterop.
- **Cinterop def file** (`shared/voice/src/iosMain/cinterop/opus.def`):
  ```
  language = Objective-C
  package = dev.puklic.voice.codec.native.opus
  headers = opus.h
  libraryPaths = $projectDir/libs/ios-arm64
  staticLibraries = libopus.a
  ```
  Three variants per arch.
- **Kotlin wrapper:** mirrors existing JNA `LibOpus.kt` interface so commonMain `expect OpusEncoder/Decoder` actual signature stays identical.

## 8. Networking — Ktor Darwin

Drop-in. Discord gateway, REST, voice WS flow through Ktor. Darwin engine wraps NSURLSession + native WebSocket; HTTP/2 + TLS via Apple's stack. Gotcha: `URLSessionConfiguration.background` cannot be used for WebSockets — keep gateway on foreground session.

**Voice UDP transport** different: iOS has `Network.framework` (`NWConnection` with `NWParameters.udp`). Existing `UdpRtpTransport` jvmMain needs `iosMain` actual. ~150 lines.

## 9. Persistence — SQLDelight native driver

```kotlin
// iosMain
actual class DriverFactory {
    actual fun createDriver(): SqlDriver =
        NativeSqliteDriver(PuklicDatabase.Schema, "puklic.db")
}
```

DB under `NSFileManager.default.urls(for: .documentDirectory, ...)`. Migrations work identically to jvm.

## 10. UI entry point + UIKit integration

```kotlin
// :ios:app iosMain
fun MainViewController(): UIViewController = ComposeUIViewController {
    PuklicApp()
}
```

Swift host:
```swift
@main
class AppDelegate: UIResponder, UIApplicationDelegate { ... }

struct PuklicApp_iOS: App {
    var body: some Scene {
        WindowGroup {
            ComposeView()  // wraps MainViewController via UIViewControllerRepresentable
        }
    }
}
```

**Decompose lifecycle bridge:** `LifecycleRegistry` at root; drive from `viewWillAppear`/`viewWillDisappear` of hosting `UIViewController`. Decompose ships `LifecycleController` helpers.

**Window insets:** Compose iOS auto-applies safe area as `WindowInsets.safeDrawing`. Audit `:shared:compose-ui` for hardcoded paddings; replace with insets.

**Material widgets on iOS — accepted v1.** Apple doesn't require HIG conformance for App Store approval.

## 11. iOS-specific systems

**Info.plist:**
- `NSMicrophoneUsageDescription` = "Puklic uses the microphone to transmit your voice in Discord voice channels."
- `UIBackgroundModes` = `[audio, remote-notification]`
- `ITSAppUsesNonExemptEncryption` = `NO` (DAVE flips this later → file exemption)
- `CFBundleDisplayName`, `CFBundleShortVersionString`, etc.

**AppDelegate:** registers for push, handles APNs token, forwards to Kotlin via `PushNotificationGateway` expect.

**Keychain:** wrap `SecItemAdd`/`SecItemCopyMatching` behind `CredentialStore` expect. Use `kSecAttrAccessibleAfterFirstUnlock` for Discord token. **Never** `kSecAttrAccessibleAlways`.

**APNs limit:** Discord's user-token push is over the gateway, not APNs. Background gateway WS dies on suspension. Realistic v1: notifications only while app foregrounded. Honest disclosure in onboarding.

**Logs:** Kermit's OSLog writer; visible in Console.app.

## 12. Build pipeline

**Plain KMP framework export, no CocoaPods plugin.**

In `:ios:app/build.gradle.kts`:
```kotlin
kotlin {
    listOf(iosArm64(), iosX64(), iosSimulatorArm64()).forEach {
        it.binaries.framework {
            baseName = "PuklicShared"
            isStatic = true
            export(projects.shared.composeUi)
            export(projects.shared.session)
        }
    }
}
```

Handwritten `ios/PuklicApp.xcodeproj` consumes framework via `Run Script` build phase invoking `./gradlew :ios:app:embedAndSignAppleFrameworkForXcode` (JetBrains' recommended path).

**Why not CocoaPods plugin?** Adds Ruby + pod resolver as build dep; flaky on CI; encourages adding 3rd-party iOS pods which would muddy dependency picture.

**CI:** GitHub Actions `macos-14` runner (Xcode 15+, arm64); `xcodebuild -scheme Puklic -destination 'generic/platform=iOS Simulator' build`. Unit tests via `iosSimulatorArm64Test`. Gate iOS jobs behind `[ios]` label on PRs or main-only.

## 13. Distribution

- **Apple Developer Program:** $99/yr. Mandatory for TestFlight + App Store.
- **TestFlight beta:** up to 10k external testers; lighter review (~24h vs days). Recommended first stop.
- **App Store:** ~50/50 rejection risk under guideline 5.2.5 ("apps that impersonate any service"). Discord can demand removal at any time.
- **Sideload via AltStore PAL (EU DMA):** since iOS 17.4 EU users can sideload via alternative marketplaces.
- **Discord ToS:** unchanged risk vs desktop. Use neutral copy "third-party client for the Discord chat service."

## 14. Risks (top 5)

1. **App Store rejection** — Apple may reject as impersonating Discord; mitigation: TestFlight + AltStore fallback path
2. **Background gateway disconnect** — iOS suspends WS within ~30s of background. No realistic workaround without Discord-side push integration (third parties can't get). Accept UX gap.
3. **libdave-iOS build complexity** — 3-4 weeks of native build work blocks DAVE on iOS. v1 ships without DAVE.
4. **Compose iOS bugs** — text input, IME, scroll physics rough edges. Pin 1.8.x, fork-and-patch if blocked.
5. **CI macOS minutes cost** — `macos-14` runners ~10× the price of ubuntu. Gate iOS jobs.

## 15. Migration phases (8 slices, 3.5-5 calendar months solo)

1. **iOS-0 — Plumbing.** Audit `puklic.kmp-library` for iOS targets. Add empty `iosMain` source sets. Compile passes; no functionality.
2. **iOS-1 — Persistence + networking actuals.** SQLDelight `NativeSqliteDriver`, Ktor `Darwin` engine, file paths, logger via OSLog, Keychain credential store.
3. **iOS-2 — Compose entry point.** `ComposeUIViewController { PuklicApp() }`, handwritten `ios/PuklicApp.xcodeproj`, Swift `AppDelegate`, `embedAndSignAppleFrameworkForXcode` task. App launches on simulator showing login.
4. **iOS-3 — Auth + chat read.** Login via Keychain token, gateway connect, render channels + messages. Working read-only Discord client on iOS.
5. **iOS-4 — Chat write.** Send messages, reactions, edit, delete, typing.
6. **iOS-5 — Attachments.** `UIDocumentPicker` for upload, Coil 3 for image preview, NSURLSession download.
7. **iOS-6 — Voice (non-DAVE).** AVAudioEngine actuals, libopus xcframework cinterop, NWConnection UDP transport, voice gateway WS via Ktor. DAVE channels show "unsupported on iOS" banner.
8. **iOS-7 — Foreground notifications + TestFlight beta.** Local notifications from gateway events. Apple Developer enrollment, App Store Connect, first TestFlight to ~20 internal testers.

## 16. Recommendation

**Build it, second priority after Linux Phase 5 closes.** KMP investment already absorbs ~70% of the work — chat UI, markdown parser, gateway, cache, persistence schema, domain model all reuse.

Honest expectations:
- Background voice/notifications worse than desktop; cannot fix without server
- App Store distribution coin flip; plan TestFlight + AltStore as real channels
- DAVE lags iOS by months until libdave-iOS arrives
- Screenshare permanently out

If these four points acceptable → high-ROI port. If user expected full desktop parity → reset expectations now.
