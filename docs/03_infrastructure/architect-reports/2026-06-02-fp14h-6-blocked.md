## §1 FP-14h-6 — shipped

### 1.1 Surface

Two SPI seams introduced so the upcoming common-main `DefaultVoiceClient`
can stay free of GPL / JVM-only DAVE + libdave + libx264 dependencies. App
Store wiring layers pass null factories; GPL desktop builds pass the
concrete JVM factories below.

| Module | File | Purpose |
|---|---|---|
| `:shared:voice-codec/commonMain` | `dev/puklic/voice/dave/spi/DaveSessionContract.kt` | `DaveSessionFactory` + `DaveSessionHandle` + `DaveSessionState` + `FrameEncryptor` + `FrameDecryptor` |
| `:shared:screencast/commonMain` | `dev/puklic/voice/screenshare/ScreenShareClientFactory.kt` | `ScreenShareClientFactory.create(...)` returning `ScreenShareClient` |
| `:shared:voice/jvmMain` | `dev/puklic/voice/dave/LibdaveDaveSessionFactory.kt` | JVM concrete factory wrapping `:shared:voice-dave`'s `DaveSession` + `mlsClient()` (Wire core-crypto, GPL) |
| `:shared:voice/jvmMain` | `dev/puklic/voice/screenshare/JvmScreenShareClientFactory.kt` | JVM concrete factory wrapping `DefaultScreenShareClient` |

### 1.2 Why `ScreenShareClientFactory` lives in `:shared:screencast`, not `:shared:voice-codec`

The first draft put both SPIs in `:shared:voice-codec/commonMain`. That
broke compilation with a circular dependency: `ScreenShareClientFactory`
needs `VideoCodec` + `ScreenSourceEnumerator`, both declared in
`:shared:screencast`. `:shared:screencast` already exposes
`api(projects.shared.voiceCodec)` (it owns `EncodedFrame` and friends in
voice-codec). Reversing that dependency would force a triangle and is not
acceptable.

Putting the screen-share SPI in `:shared:screencast` instead is the
conceptually right answer — the contract belongs with the types it consumes.
The DAVE SPI stays in `:shared:voice-codec` because it has no screencast
dependencies; only voice-api + serialization-json.

### 1.3 Tests (commonTest)

- `:shared:voice-codec/commonTest/.../dave/spi/DaveSessionFactoryContractTest.kt`
  — pins factory shape, frame en/decryptor null pass-through, state flow propagation, value semantics on `DaveSessionState`.
- `:shared:screencast/commonTest/.../screenshare/ScreenShareClientFactoryContractTest.kt`
  — pins factory shape, propagates SSRC suppliers + codec choice through to the returned client.

Both run on JVM (Kotlin/Native common-test execution depends on existing
project setup; the SPI compiles for iosArm64 — verified explicitly).

## §2 FP-14h-7 / FP-14h-8 / FP-14h-9 — blocked

### 2.1 The h-7 blocker

The original brief had FP-14h-7 promote `DefaultVoiceClient` from
`:shared:voice/jvmMain` to `:shared:voice-codec/commonMain`. Inspection
of the 728-line `DefaultVoiceClient` shows it directly uses these
JVM-only / not-yet-promoted types:

| Type | Lives | Status |
|---|---|---|
| `dev.puklic.voice.pipeline.PlaybackPipeline` | `:shared:voice/jvmMain` | Uses `ConcurrentHashMap`, `ConcurrentLinkedQueue`, `Dispatchers.IO`, `System.nanoTime()`. Move is its own FP-14h-2 follow-up, explicitly out of scope per FP-14h-2d §1. |
| `dev.puklic.voice.pipeline.IncomingVideoPipeline` | `:shared:voice/jvmMain` | Same posture as PlaybackPipeline. |
| `dev.puklic.voice.codec.transport.JvmVoiceUdpTransportFactory` | `:shared:voice-codec/jvmMain` | Already common-contract via `VoiceUdpTransportFactory`; `DefaultVoiceClient` must take an injected factory rather than calling `JvmVoiceUdpTransportFactory.create(...)` directly. |
| `dev.puklic.voice.audio.audioCapture()` / `audioPlayback()` / `listAudioDevices()` | `:shared:voice-codec/jvmMain` | JVM-only top-level functions. The FP-14h-7 brief explicitly hands these in as ctor params, fine. |
| Various concurrency primitives (`AtomicInteger`, `ConcurrentHashMap`) | JDK | Migrate to `kotlinx.atomicfu.atomic` + `Mutex`+`MutableMap`, per brief. |
| `dev.puklic.voice.codec.transport.JvmVoiceUdpTransportFactory.create(...)` direct call | `:shared:voice-codec/jvmMain` | Replace with constructor-injected `VoiceUdpTransportFactory`. |

Even with the audio injection + concurrency migration done, **PlaybackPipeline + IncomingVideoPipeline still pin
DefaultVoiceClient to jvmMain.** Moving them is a FP-14h-2 follow-up slice
that the FP-14h-2d implementation note explicitly deferred (it would have
required moving them out of `:shared:voice/jvmMain` into
`:shared:voice-codec/commonMain` with full concurrency rewrites).

### 2.2 The h-8 + h-9 dependency

h-8 (`DI flip from NoOpVoiceClient to DefaultVoiceClient`) is downstream
of h-7. It cannot land while `DefaultVoiceClient` is still JVM-only —
`:ios:app` cannot construct it from `IosDependencyGraph`.

h-9 (`F-16..F-21 nits + CLAUDE.md Platforms table flip from "⚠ ships as
NoOpVoiceClient" to "✅ AppleNativeVoice via DefaultVoiceClient"`) is
downstream of h-8. The table flip cannot be made truthful until iOS +
Mac App Store actually instantiate `DefaultVoiceClient`.

### 2.3 Aggregate stop-criterion

Per HARD RULE #2 ("NEVER TEMPORARY, ALWAYS CONCEPTUAL"): partial promotion
of `DefaultVoiceClient` would introduce expect/actual stubs for
`PlaybackPipeline` / `IncomingVideoPipeline` with empty iOS actuals,
violating the rule. Half-flipped DI graphs (`DefaultVoiceClient` in
commonMain but inert on iOS) would lie about the Platforms table.

Therefore FP-14h-7, FP-14h-8, FP-14h-9 must wait for a prerequisite
slice that promotes `PlaybackPipeline` + `IncomingVideoPipeline` to
`:shared:voice-codec/commonMain` with proper KMP concurrency primitives
(atomicfu + Mutex), or accept that `DefaultVoiceClient` belongs in a
**new** higher-level module that depends on both `:shared:voice-codec`
and `:shared:screencast`. The latter is structurally cleaner: voice-codec
sits below screencast, so DefaultVoiceClient (which needs both) cannot
live in voice-codec without a circular dependency.

## §3 Next-step recommendation

Open a new tracking issue **FP-14h-10 "Promote PlaybackPipeline +
IncomingVideoPipeline to commonMain with atomicfu/Mutex"** under #62.
Once that lands, FP-14h-7 (a) loses its main blocker, (b) can move
`DefaultVoiceClient` into a new `:shared:voice-orchestrator` module
(commonMain), and (c) lets h-8 + h-9 land in sequence.

Alternative path: define `DefaultVoiceClient` directly in
`:shared:screencast` — that module already depends on everything
`DefaultVoiceClient` needs and is KMP-clean. The downside is conceptual:
"screencast" is a misleading owner for the full voice orchestrator.

Decision deferred to user — both are conceptually clean; pick before
FP-14h-7 starts.
